Cost comparison / Fictional worked example

When cache support
costs more.

A cheap cache-read rate helps only when enough reusable tokens actually hit cache. Compare the full workload before choosing a plan.

2026-10-10 · Maintained by the TokenDos operator · All prices are fictional, with no real-provider cost ranking.

Here, A becomes cheaper above a 67.90% reusable-token hit rate. If only A adds a 5.5% top-up fee, the threshold rises to about 76.91%.

Rounded thresholds are specific to these prices and assumptions. Extra cache-write charges are excluded and all purchased credit is assumed used.

Keep the workload fixed

Run 1,000 tasks. Each has 2,000 fresh input tokens, 6,000 reusable input tokens and 1,000 output tokens: 8M input tokens and 1M output tokens in total.

B bills all input at its ordinary rate. A charges misses at $3 / 1M and hits at $0.30 / 1M. Extra cache writes, tools, retries, taxes and exchange costs are excluded; add them when applicable.

Count reusable tokens, then compare

Let h be the fraction of the 6M reusable tokens served from cache, from 0 to 1. The denominator is neither all input tokens nor the number of requests with any hit.

A = 2 × 3 + 6 × [h × 0.30 + (1 − h) × 3] + 1 × 15
  = 39 − 16.20 × h
B = 8 × 2 + 1 × 12 = 28

A costs less when h > 11 / 16.20, or about 67.90%. At the exact boundary, the costs are equal.

A top-up fee can reverse the result

If only A adds a 5.5% fee on purchased credit, and all purchased credit is used, the condition becomes (39 − 16.20 × h) × 1.055 < 28. A now needs a hit rate above about 76.91%.

At 70% hits, A's model charge is $27.66 versus B's $28.00. With A's fee, the required cash is $29.1813, so B costs less under these assumptions.

  1. Put reusable misses into uncached input and hits into cache reads. At 70%, that is 3,800 uncached and 4,200 cached tokens per task.
  2. For a plan billing all input normally, set its cache-read rate equal to its ordinary input rate. This keeps B's total input cost unchanged.
  3. Replace fictional rates with one node's full quote in one currency. Include applicable cache writes and other charges in the workload's total extra charges.
  4. Include only eligible bonus credit you can use. Record actual bills separately from estimates.

The calculator uses the same token split for both plans. If both cache input at different hit rates, calculate each plan's usage separately before comparing. Changing the currency label does not convert exchange rates.

Check real cache and task conditions

Expiry, prefix length, request spacing, routing and cache-write rules affect actual hits and cost. Check usage-field definitions to avoid counting cached input twice. Keep task volume fixed and check that outputs meet the same task requirements.

This is an arithmetic example, without same-condition cross-provider calling tests. Estimates do not establish model identity, service reliability or actual billing.
