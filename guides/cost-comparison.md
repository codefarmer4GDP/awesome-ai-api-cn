# API 成本怎么比较：单价、缓存、充值和套餐

先固定自己的任务，再计算各服务完成这些任务需要花多少钱。模型名称相同，也要确认版本、节点、协议、上下文和工具设置；这些条件不一致时，只能比较方案预算，不能同时推导质量排名。

本文是核算方法，以下 A、B 都是虚构方案，数字不代表任何平台的报价。服务资料见 [主指南](../README.md)。

也可以使用 [在线双方案计算器](https://codefarmer4gdp.github.io/awesome-ai-api-cn/#calculator)，填写同币种报价、输入输出与缓存用量、充值附加费和实际可用赠送额度，再分享链接或导出估算 JSON。计算器假定余额价格与现金按 1:1 兑换，平台存在其他兑换率时先换算单价；未自动计入的缓存写入、工具与重试费用可以填入「其他项目」合计。周期套餐仍需按本文的方法逐周核算。

## 1. 把价格换成同一单位

| 原始标价 | 换成每 100 万 Token |
| --- | --- |
| $0.003 / 1K Token | $3 / 1M Token |
| $0.000003 / Token | $3 / 1M Token |
| ¥21 / 1M Token | 仍为 ¥21；换成美元时另记汇率和日期 |

平台展示的美元额度未必等于美元现金。先核对充值金额、到账额度、分组倍率和页面单价之间的关系；若页面已包含倍率，不要重复乘一次。Token、请求、图片、秒和会员套餐也不能直接用一个单位比较。

## 2. 把输入、输出和缓存拆开

对互不重叠的计费类别，按以下方式相加：

```text
模型费用 = 未缓存输入量 × 输入单价
         + 缓存读取量 × 缓存读取单价
         + 缓存写入量 × 对应期限的写入单价
         + 输出量 × 输出单价
```

Token 单价都先换成每 1M，再把用量除以 1,000,000。若厂商将缓存写入作为输入价之外的附加费，应按其规则分别计入基础费和附加费。不同协议的输入用量可能包含缓存，也可能另列缓存字段；不能直接把所有字段相加。推理 Token 是否计入输出、工具或长上下文是否单独收费，也需核对。

### 示例：输入单价更低，整项任务可能更贵

假设同一个任务重复 1,000 次，每次有 2,000 个新输入 Token、6,000 个可复用输入 Token，以及 1,000 个输出 Token。为了演示，假设 A 的可复用输入全部已命中缓存，首次建缓存费用另计；B 不支持这项缓存。

| 项目 | 虚构方案 A | 虚构方案 B |
| --- | ---: | ---: |
| 输入单价（$/1M） | 3 | 2 |
| 缓存读取单价（$/1M） | 0.30 | 不支持，按普通输入计费 |
| 输出单价（$/1M） | 15 | 12 |
| 输入费用 | 2M × $3 = $6 | 8M × $2 = $16 |
| 缓存读取费用 | 6M × $0.30 = $1.80 | 已计入输入费用 |
| 输出费用 | 1M × $15 = $15 | 1M × $12 = $12 |
| 模型费用合计 | $22.80 | $28.00 |

如果 A 另收按充值额计算的 5.5% 费用，且本次额度恰好全部用完，所需现金为 $22.80 × 1.055 = $24.054。实际还应加入首次写缓存、最低手续费、税费及汇兑等适用项目。此例说明需要比较完整任务；没有替任一家平台作价格结论。

## 3. 充值赠送不等于同百分比的现金折扣

假设花 $10 得到 $10 余额与 $1 代金券，且券全部满足条件并用完，则 $11 可用额度对应 $10 现金，额度成本系数为 10 / 11 ≈ 0.9091，相当于约 9.09% 的现金成本下降。这里的“赠送 10%”与“打九折”是两个不同口径。

券未领取、过期、受模型限制或无法用完时，应只计入实际能使用的部分。首充活动与邀请奖励通常有资格条件，不能作为所有用户长期预算的固定折扣。

预付余额未用完时，可分别记录本期现金支出、已消耗额度和剩余可用余额，避免把一次充值全部算成当期任务成本。未过期的余额与已失效的券也应分别列出。

## 4. 按周刷新套餐，要逐周核算

假设四周套餐售价 ¥400，每周发放 $100 平台额度，未用部分不结转。用户每周分别消费 $20、$20、$80、$0，总共实际利用 $120，而不是标称的 $400。

先按套餐的实际计价规则估算这些任务若按量购买要花多少现金，再与 ¥400 套餐费加上超额费用比较。平台美元额度不等于厂商现金余额；额度被用完也不必然表示套餐划算。时间窗口、分组倍率、工具限制和适用模型都影响结果。

## 5. 把失败和重试计入完成任务的成本

```text
每个成功任务的平均费用 = 所有已计费尝试的费用 / 成功完成的任务数
```

保存失败和重试样本，注明失败是否收费、是否退款、重试是否重复执行。成功任务需按业务标准判断；仅收到 HTTP 200 不能代表任务完成。

会员会话共享还应考虑可用席位、供应端在线时间、额度窗口、排队和是否适用自己的客户端。TokenDos 的供应方报价与活动、AIGoCode 的周期额度、OpenRouter 的充值费用，都应代入各自规则计算，不能只比较首屏最低单价。

## 可复制的记录

可以从 [实测记录 JSON 模板](../examples/evaluation-record.template.json) 开始记录。字段为空表示未取得信息；模板本身没有进行任何调用，也不构成服务质量证据。

| 必填记录 | 用途 |
| --- | --- |
| 模型、节点、协议、日期和请求设置 | 判断任务与价格是否可比 |
| 原始价格链接、币种、单位、倍率 | 重算模型费用 |
| 输入、输出、缓存字段及其定义 | 避免重复计算用量 |
| 实际扣费、充值费用、已使用优惠 | 核对现金成本 |
| 全部尝试、失败、重试和成功任务数 | 计算完成任务的成本 |
