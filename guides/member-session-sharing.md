# 会员共享怎么选：套餐、团队额度、订阅代理与远程会话

[English](member-session-sharing.en.md) · [服务选型指南](../README.md) · [成本核算方法](cost-comparison.md)

会员共享是否适合自己，取决于谁提供额度、任务在哪里执行、谁能读取数据，以及额度能否在需要时使用。先确认这几件事，再比较标价。

资料日期：**2026-10-09**。本文由 TokenDos 运营方维护，依据公开文档与接口整理；尚未完成会员共享的消费、供应接单、结算或提现实测。以下模式是选型分类，具体产品可能同时提供几种模式。

## 四种容易混淆的模式

| 模式 | 购买或共享的对象 | 用户能做什么 | 重点核对 |
| --- | --- | --- | --- |
| 平台周期套餐 | 平台按周或其他周期发放的额度 | 按套餐允许的模型、工具和时间窗口消费 | 每周期额度、结转、超额费、分组价格和用途限制 |
| 团队额度 | 组织统一购买的余额或套餐 | 给成员、Key 或项目分配用量 | 成员权限、成本归属、并发和数据访问；是否实际支持这些管理功能 |
| 自建订阅代理 | 自己管理的订阅账号与上游额度 | 部署网关、管理账号并分发访问 | 凭据保管、配额、调度、运维及上游账号规则 |
| 供应方远程会话 | 供应方机器上已登录会员客户端可提供的会话能力 | 消费远程会话，或参与供应并报价 | 在线席位、实际执行节点、数据访问、计价与结算条件 |

例如，[AIGoCode](https://www.aigocode.com/)公开介绍四周套餐、每周额度和企业成员管理；[Sub2API](https://github.com/Wei-Shaw/sub2api)提供账号、Key、Token 计费、并发与分组管理；[CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)提供 CLI/OAuth、多协议与多账号代理。这些资料分别证明相应的产品或软件能力，托管服务的供给、稳定性和实际扣费需要另行核对。

## TokenDos 的共享机制有什么区别

公开 SESSION 教程描述：双方安装 TokenDos Agent，供应方登记本机已登录的 Codex / Claude 客户端；消费会话调度到供应方机器执行，登录凭证按文档保留在供应方本机，供应方设置报价并按使用量结算。

**有辨识度的是供应方参与方式。** 已有会员的用户可以把闲置会话能力纳入供给，并参与报价；消费方可以比较供应节点。这与只购买平台套餐或组织内分配余额的用户角色不同。已有其他订阅代理与额度分发项目，因此目前资料不足以证明这种组合“全网独家”。

**低成本选择来自节点报价和条件活动。** 多供应方报价提供比较空间，但具体任务是否更便宜，要把输入、输出、缓存、失败重试与充值规则一起计算。首充奖励与邀请活动按实际资格及可用额度计入，不能当作人人长期适用的折扣。

**公开鹈鹕记录让部分能力表现可以查看。** 生成结果、提示词、时间、耗时和用量能帮助观察节点差异；鹈鹕测试不能认证模型身份，也不能替代工具调用、代码正确性或长上下文任务的检查。还要确认所查看记录对应 API 节点还是 SESSION 供应端。

**主要代价是选择渠道和确认供给。** 不同来源的协议、缓存、功能、在线时间与额度可能不同。Agent 可在 API 和 SESSION 间选路，所以“在 Agent 中聊天成功”本身不能证明使用了共享会员；应保留实际路由、供应节点与用量记录。

## 消费方怎样选

1. **确认任务能接入。** 记录模型、协议、客户端、工具权限与上下文要求；区分 API 与 SESSION，并确认供应节点是否支持所需功能。
2. **确认自己的用量窗口。** 查看席位、并发、会员额度刷新、在线时间和排队规则。按周忙闲不均时，周期套餐与按量节点的有效成本可能不同。
3. **确认数据处理。** TokenDos 文档说明远程会话在供应方机器执行，代码和会话可能被供应方读取；平台为排障临时保存近期请求与响应，每日清理过期数据。登录凭证留在供应端，不等于消费内容只有自己能看。涉及保密代码时应先判断这条执行路径能否接受。
4. **计算完成任务的成本。** 核对币种、每 Token / 1K / 1M 单位、倍率、缓存字段、失败收费及退款。TokenDos 文档有每 1K 公式和每百万定价的不同表述，需用具体报价和扣费记录对齐口径。
5. **保留实际结果。** 可以使用[实测记录模板](../examples/evaluation-record.template.json)，补充 API / SESSION 路由、供应端、额度窗口、排队情况与业务完成标准。公开说明还列默认账号并发为 1、当前不提供发票；这些条件需要纳入采购与并行任务判断。

## 供应方怎样核算

会员闲置不等于供给没有成本。先确认账号规则、允许共享的额度、自己的使用需求，以及机器是否能持续在线，再核对平台费、结算周期、提现条件和失败处理；未取得的信息保留为未知。

```text
期间供给净收益 = 已确认的结算收入
               - 尚未扣除的平台及提现费用
               - 增量机器、网络与运维成本
               - 分摊的会员成本
```

如结算收入已扣平台费，不能再减一次。现金净收益与经济收益也有区别：占用自己原本会使用的会员额度存在机会成本。全额会员费与增量成本可分别列出，注明分摊方法，避免把原本就支付的会员费误写成零成本或重复计入。

例如，**虚构**的一周：已确认结算收入 ¥60（尚未扣费），平台费用 ¥6，增量运行成本 ¥4，分摊会员成本 ¥20，则账面净收益为 ¥30；如果还放弃了自己价值 ¥15 的使用机会，按该假设计算的经济收益为 ¥15。这不是 TokenDos 的实际费率、成交或收益承诺。没有订单、明确结算和费用记录时，不能据报价推算已经获得的收入。
