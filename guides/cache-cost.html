成本核算 / 虚构报价算例

支持缓存，
也可能更贵。

缓存读取单价低，只有足够多的可复用 Token 真正命中时才省钱。选方案之前，先算完整任务。

2026-10-10 · 由 TokenDos 运营方维护 · 全文为虚构报价，不构成真实平台的价格排名。

本例中，可复用 Token 的命中率超过 约 67.90%，A 才更便宜；若只有 A 加收 5.5% 充值费，门槛升到 约 76.91%。

门槛经过四舍五入，只适用于本例报价和假设。未计额外缓存写入费，并假定购买额度恰好全部用完。

先固定任务量与报价

一共执行 1,000 次任务。每次有 2,000 个新输入 Token、6,000 个可复用输入 Token，以及 1,000 个输出 Token；合计输入 8M、输出 1M。

虚构报价 · 美元 / 百万 Token
计费项目方案 A方案 B
普通输入$3.00$2.00
缓存读取$0.30$2.00
输出$15.00$12.00

B 的全部输入均按普通输入价计费。A 的未命中部分按 $3 / 1M、命中部分按 $0.30 / 1M 计费。这里未计额外缓存写入、工具、重试、税费和汇兑费用；实际适用时需补入。

按可复用 Token 算命中率

设 h 为 6M 可复用 Token 中命中缓存的比例，取值 0 到 1。分母不是全部输入 Token，也不是命中请求的数量。

A = 2 × 3 + 6 × [h × 0.30 + (1 − h) × 3] + 1 × 15
  = 39 − 16.20 × h
B = 8 × 2 + 1 × 12 = 28

A 更便宜需要 h > 11 / 16.20，即约 67.90%。在精确临界值处，两方案费用相同。

充值费会改变结论

如果只有 A 对购买额度加收 5.5%，且额度恰好全部用完，需要满足 (39 − 16.20 × h) × 1.055 < 28。A 的命中率门槛随之升到约 76.91%。

70% 命中时，A 的模型费用为 $27.66，低于 B 的 $28.00；加上充值费，A 需要 $29.1813 现金，本例条件下 B 更便宜。

怎样填入自己的报价

  1. 将未命中的可复用 Token 加入「未缓存输入」，命中部分填入「缓存读取」。70% 命中时，每次分别为 3,800 和 4,200 Token。
  2. 对全部输入按普通价计费的方案，将缓存读取单价填成普通输入单价；这样 B 的总输入费用不变。
  3. 用同币种、同一个节点的完整报价替换虚构费率；适用的缓存写入等费用填入整个任务量的「其他项目」合计。
  4. 赠送额度只计入实际符合条件且能用完的部分。预算与真实账单分开记录。

计算器对两方案使用相同的 Token 拆分。若两方案都支持缓存且实际命中率不同，需先分别计算各自用量再比较。切换币种标记不会进行汇兑。

预填链接里的报价与用量都是虚构示例。本文无需 JavaScript 即可阅读；计算器需要启用它，并在浏览器本地运行，无需 API Key。

再核对真实缓存与任务条件

有效期、前缀长度、请求间隔、路由和写入规则会影响真实命中率与费用。先确认用量字段是否包含缓存，避免重复计算；同时固定任务量，确认输出满足相同业务要求。

本文是数学算例，尚未完成同条件跨平台调用实测。预算估算不能证明模型身份、服务可靠性或实际扣费。
